## 1. Тест дизайн: сонголт ба төлөөлөх утга

| Сонголт | Ангиуд | Төлөөлөх утга (collection-д ашигласан) |
|---|---|---|
| studentID | идэвхтэй / идэвхгүй / байхгүй | `status: active` / `status: inactive` / PUT хийгээгүй ID |
| Оюутны үзсэн хичээл ба урьдач | хангана / огт хангахгүй / хагас хангана | `["CS201"]` vs `[CS201]`; `[]` vs `[CS201]`; `[CS201]` vs `[CS201, CS202]` |
| courseID | байгаа / байхгүй | PUT хийсэн ID / PUT хийгээгүй ID |
| Хичээлийн урьдач нөхцөл | байхгүй (хоосон) / байгаа | `[]` / `["CS201"]` |
| Хүсэлтийн формат | зөв / талбар дутуу / буруу JSON | бүтэн body / `{"studentID":...}` (courseID-гүй) / `{bad json` |

Боломжгүй хослол: оюутан **байхгүй** үед "оюутны үзсэн хичээл" гэсэн сонголт утгагүй (үзсэн хичээл хадгалах бичлэг байхгүй). Мөн хичээл **байхгүй** үед "урьдач нөхцөл" гэсэн сонголт утгагүй. Иймд эдгээр хослолыг тусад нь тест болгоогүй.

## 2. Спецификаци (13)

| ID | Тохиолдол | Хүлээгдэх статус | Хүлээгдэх result |
|---|---|---|---|
| S01 | Идэвхтэй оюутан, урьдач хангасан (happy path) | 201 | `OK` + `registrationID` тоо |
| S02 | Оюутан байхгүй | 200 | `ERROR_NO_STUDENT` |
| S03 | Идэвхгүй оюутан | 200 | `ERROR_INACTIVE_STUDENT` |
| S04 | Хичээл байхгүй | 200 | `ERROR_NO_COURSE` |
| S05 | Урьдач нөхцөл огт хангаагүй | 200 | `ERROR_PREREQUISITES`, missing `["CS201"]` |
| S06 | Урьдач нөхцөл хагас хангагдсан | 200 | `ERROR_PREREQUISITES`, missing `["CS202"]` |
| S07 | Хязгаар: урьдач нөхцөлгүй хичээл, хоосон coursesTaken | 201 | `OK` + `registrationID` тоо |
| S08 | Давхар алдаа: оюутан ба хичээл хоёулаа байхгүй | 200 | `ERROR_NO_STUDENT` |
| S09 | Давхар алдаа: идэвхгүй оюутан + хичээл байхгүй | 200 | `ERROR_INACTIVE_STUDENT` |
| S10 | Давхар алдаа: идэвхгүй оюутан + урьдач дутуу | 200 | `ERROR_INACTIVE_STUDENT` |
| S11 | Давхар алдаа: оюутан байхгүй + урьдач нөхцөлтэй хичээл | 200 | `ERROR_NO_STUDENT` |
| S12 | Хязгаар: courseID талбар дутуу | 400 | `ERROR_BAD_REQUEST` |
| S13 | Буруу JSON | 400 | `ERROR_BAD_JSON` |

Давхар алдааны хүлээлтийг (S08-S11) таамаглаагүй, эхлээд сервер дээр curl-ээр туршиж тогтоосон. Серверийн шалгах дараалал: **оюутан байхгүй → оюутан идэвхгүй → хичээл байхгүй → урьдач дутуу**.

Тест бүр бие даасан: өөрийн setup PUT хүсэлтүүдийг өөрөө хийнэ, setup ба POST нэг ID-г ашиглана (`LAB5_Sxx_...`). `registrationID`-ийн яг утгыг шалгаагүй, зөвхөн тоо мөн эсэхийг шалгасан.

## 3. Ажиллуулах

```bash
node server.js
mkdir -p results
newman run lab05-collection.json 2>&1 | tee results/newman-pass.txt
echo "exit=${pipestatus[1]}" | tee -a results/newman-pass.txt
```

## 4. Үр дүн

| Ажиллуулалт | Файл | requests | assertions executed | assertions failed | exit code |
|---|---|---|---|---|---|
| PASS | `results/newman-pass.txt` | 30 | **47** | 0 | 0 |
| FAIL (S01 oracle зориуд буруу) | `results/newman-fail.txt` | 30 | 47 | 1 | 1 |
| DOWN (сервер унтраасан) | `results/newman-down.txt` | 30 (бүгд errored) | 30 | 30 | 1 |

Тестийн тоо: **47 assertion** (13 спецификац, 30 request: 17 setup PUT + 13 POST), энэ нь `results/newman-pass.txt`-ийн `assertions executed` тоотой таарна.

**FAIL:** `lab05-collection-fail.json` нь үндсэн collection-ийн бүтэн хуулбар бөгөөд зөвхөн S01-ийн статусын oracle-ийг 201-ийн оронд 200 болгосон. Үр дүн: `expected response to have status code 200 but got 201`, exit code 1. Ийм байдлаар CI quality gate тест унахад pipeline-ийг зогсооно.

**DOWN:** сервер унтарсан үед `newman-down.txt`-д `connect ECONNREFUSED 127.0.0.1:3000` мөрүүд байна, exit code 1. Энэ нь **интерфейсийн алдаа** (холболт тогтоогдоогүй тул HTTP хариу огт ирээгүй), харин FAIL нь **oracle-ийн алдаа** (сервер хариу өгсөн, гэхдээ хариу минь хүлээсэн утгатай таарсангүй). DOWN дээр assertions 30 гэсэн тоо PASS-ийн 47-аас бага, учир нь хариу байхгүй үед `pm.response.json()` JSONError шидэж, тест script дунд нь зогссон.

## Дүгнэлт

Дизайны 5 алхмаас спецификац бичих алхам хамгийн их бодол шаардсан, учир нь давхар алдааны үед сервер аль алдааг түрүүлж буцаахыг заавар хэлээгүй. Тиймээс S08-S11-ийн хүлээлтийг таамаглахын оронд curl-ээр урьдчилж туршиж, шалгах дараалал нь оюутан байхгүй, идэвхгүй, хичээл байхгүй, урьдач дутуу гэсэн дараалалтай гэдгийг тогтоосон. Боломжгүй хослол нь оюутан байхгүй үед "үзсэн хичээл" гэсэн сонголт, хичээл байхгүй үед "урьдач нөхцөл" гэсэн сонголт байсан, учир нь байхгүй бичлэгт эдгээр утга оршдоггүй. Тестүүд серверээс согог илрүүлээгүй, 13 спецификац бүгд хүлээсэн утгатай таарсан. Харин S06 (хагас хангагдсан урьдач) нь серверийн missing жагсаалт зөвхөн дутууг (CS202) буцаадгийг баталсан. Тест бүрийг бие даасан болгохын тулд setup болон POST-д нэг ID ашиглаж, registrationID-ийн яг утгыг шалгаагүй, учир нь сервер дахин асах хүртэл тоо хуримтлагддаг. FAIL ба DOWN хоёр нь юугаараа ялгаатайг харсан: FAIL-д сервер хариулсан ч oracle таарахгүй, DOWN-д хариу огт ирэхгүй тул assertion-уудын тоо ч өөр болдог. README-ийн тоо бүрийг results/ дахь файлтай тулгаж бичсэн. Collection-ийг Postman-ийн GUI-гаар гараар бичихийн оронд script-ээр үүсгэсэн нь спецификацийг өөрчлөхөд хоёр collection-ийг нэг дор шинэчлэх боломжийг өгсөн. Дараагийн удаа Postman-д import хийж GUI-аар нэг удаа шалгах нь зүйтэй.
